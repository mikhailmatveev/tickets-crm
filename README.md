## Tickets CRM

### Проект тестовой системы CRM для сбора и обработки тикетов

В системе есть следующие взаимодействующие друг с другом сущности:
- Клиенты
- Администраторы
- Менеджеры

Бизнес-процесс в рамках данного проекта следующий:
- Клиент создаёт тикет
- Менеджер смотрит новые заявки и начинает работу
- Когда менеджер завершает работу по тикету, он пишет ответ клиенту и нажимает кнопку "Отправить", после чего, тикет переводится в статус "Завершён"
- Клиент видит ответ менеджера и статус тикета на странице `/widget?ticket_id=<ID тикета>`

## Создание тикета

Клиент заходит на страницу `/widget`, заполняет необходимые поля: имя, e-mail, телефон, тема сообщения и текст сообщения
Так же есть возможность прикреплять файлы к тикету

Клиент может создавать не более одного тикета в сутки с одного email или телефона.

После успешного создания тикета клиенту показывается диалог с сообщением, что тикет успешно создан и ссылкой на сам тикет
вида `/widget?ticket_id=<ID тикета>`, где он может увидеть ответ от менеджера, который занимался его тикетом, а так же статус этого тикета

## Админ-панель

Доступна менеджерам и администраторам и недоступна клиентам

| Страница       | Описание                           | Доступ                    |
|----------------|------------------------------------|---------------------------|
| `/`            | Список тикетов и фильтр по тикетам | Администраторы, менеджеры |
| `/ticket/{id}` | Детали тикета                      | Администраторы, менеджеры |
| `/statistics`  | Статистика по тикетам              | Администраторы, менеджеры |
| `/users`       | Зарегистрированные пользователи    | Администраторы            |

Администраторы в отличие от менеджеров могут добавлять/удалять пользователей, назначать им права и обновлять пароль

### Добавление пользователя

При добавлении нового пользователя в систему ему приходит на почту уведомление со ссылкой на страницу о подтверждении входа,
которая существует в течение 60 минут, после чего, придётся запросить уведомление повторно со страницы `/verify-email`,
нажав на кнопку "Отправить повторно"

### Обновление пароля

При нажатии на кнопку обновления пароля соответствующему пользователю придёт уведомление на почту о том,
что его пароль был изменён и с актуальными доступами

## Развёртывание
1. `git clone git@github.com:mikhailmatveev/tickets-crm.git`
2. `cp .env.example .env`
3. `cp .env.testing.example .env.testing`
4. `Настроить .env`
5. `Настроить .env.testing`
6. `./deploy.sh`

## Параметры развёртывания

| Параметр                      | Описание                                                                                  |
|-------------------------------|-------------------------------------------------------------------------------------------|
| `./deploy.sh -h`              | Показывает справку                                                                        | 
| `./deploy.sh --dry-run`       | Деплой на холостую. Показывает только этапы выполнения команд без выполнения самих команд |
| `./deploy.sh --force-rebuild` | Деплой с принудительной пересборкой образов                                               |

Перед запуском деплоя убедиться, что у файла `deploy.sh` есть права на выполнение. Если нет, то надо выполнить `chmod +x deploy.sh`

При успешном выполнении деплоя будет такой вывод
```
[+] Running 1/1
✔ Container Tickets-CRM_node  Started  0.2s
Развёртывание завершено.
```

## Админ

В приложении должен существовать главный админ, в случае, если не будет никаких пользователей

В `.env` это следующие параметры (на боевом меняем на свои)

```
ADMIN_NAME="John Smith"
ADMIN_EMAIL="admin@example.com"
ADMIN_PASSWORD=password
```

## Telescope

Доступен по адресу `/telescope`

Проверка прав для доступа к Telescope осуществляется только в `production` окружении,
то есть, если `APP_ENV=production` в `.env`. В остальных случаях Telescope будет доступен пользователям с любой ролью

Настройки в `.env`
```
TELESCOPE_ENABLED=true
```

## Queue и Redis

В проекте используется Redis для получения и отправки уведомлений по почте с помощью очередей (Queue) 

## Mailpit

Доступен только для `local/dev` окружения

Требуется для проверки отправки сообщений на почту при создании нового пользователя или при изменении пароля пользователю

Настройки в `.env`
```
MAILPIT_SMTP_PORT=1025
MAILPIT_UI_PORT=8025
```

## Документация

## Production

**На текущем этапе пока требует тестирования**

Для её работы требуется файл окружения `.env.production` со своими настройками для боевой сборки - HTTPS, Let's Encrypt, а так же зарегистрированные `DOMAIN` и `EMAIL`

Использует `docker-compose.production.yml` и `docker/nginx/production.conf` файлы

Так же, в режиме `production` выполнятся только основные сидеры - `RoleAndPermissionSeeder` и `AdminSeeder`, для того,
чтобы можно было работать только с реальными данными
